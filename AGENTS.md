# Argos Inc portfolio and design-agent guidance
For all user-interface work in this repository, use `argos-design-system/ARGOS_DESIGN_PRINCIPLES.md` as the Argos master design standard.

The Argos Inc parent identity is the approved oval engraved emblem and plain serif "ARGOS INC" wordmark (no period, no underline). The portfolio should show real engineering projects, diagrams and proof, not generic AI graphic motifs.

Apply the 20 anti-generic rules: no filler badges, unnecessary labels, random italics, decorative glows, or placeholder metrics. Use strong whitespace grouping, accurate typography and meaningful primary CTAs. Check all accessibility, responsive, loading, error and success criteria in the master standard.

Never include financial records, private rugby/fitness health data or credentials in this public repo. Do not claim mockups are actual data or working features.
## Shared design craft — mandatory for Codex
Argos Inc is a parent portfolio; this repository must retain its own product identity. Product-specific colours, fonts, themes and layouts are not standardised across apps. Shared rules are craftsmanship: hierarchy, baseline/optical alignment, grouping with spacing, concentric radii, restrained borders, fluid and stable typography, tabular figures, meaningful truncation, consistent icon weight, accessible contrast, correct state feedback, reduced-motion-aware animation, responsive behaviour and no filler UI. Always prefer clear interactions and accurate product data over decoration. The master design document's colour palettes and background techniques are optional references only. Preserve the actual product name, style and existing functionality. Test using before/after screenshots at mobile and desktop widths when visual testing is available.

### Implementation resources
Before any portfolio UI changes, read `argos-design-system/UI_IMPLEMENTATION_PLAYBOOK.md`, `argos-design-system/UI_QUALITY_CHECKLIST.md`, `argos-design-system/SCREENSHOT_SOURCE_AUDIT.md` and `argos-design-system/DESIGN_TOOL_REFERENCES.md`. Follow existing product style and do not assume screenshots are implemented merely because documentation exists.

## Apple-inspired interaction guidance
The repository includes `.agents/skills/apple-design/SKILL.md` (Emil Kowalski, MIT; see adjacent license and upstream attribution). Before changing gesture-driven interfaces, touch feedback, sheets, drawers, popovers, animation, motion-sensitive typography or layered materials, read that skill and apply it selectively. Prefer instant response, interruptible motion, spatial consistency, meaningful feedback, reduced-motion accessibility, and user control. **Do not** force Apple visual styling, glass, a common theme, extra motion or new dependencies onto this product. Its independent identity and existing workflows remain authoritative. For static dashboards and data tables, use ordinary Argos UI quality standards first.
